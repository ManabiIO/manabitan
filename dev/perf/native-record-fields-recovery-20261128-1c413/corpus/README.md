# New untimed native record-field corpus correctness kit

This is newly reconstructed source for a correctness-only study. It is not the lost
local driver, a recovered historical receipt, a browser benchmark, or a performance
nomination. No code in this kit has been executed during its authoring/review phase.

## Scope and ordering

The immutable baseline is
dcfc02a0a5534929b1e9fa1f2801ec7a0784ea16. The candidate is the separately reviewed,
new reconstructed production fields source identified by the enclosing correctness
workflow and its source guard.

The fixed dictionary order is JMdict, Jitendex, then VNDB. Each dictionary runs once
in a fresh baseline A process and once in a fresh candidate B process, in A then B
order. Each process owns an empty disk-backed OPFS adapter and a fresh real SQLite
engine using a nonpersistent :memory: database. The first failed smoke, source
check, import, parity check, activation gate or cleanup stops this acquisition.
There are no retries, replacement imports, alternative readiness waits or timing
comparisons.

Before any full corpus, a separate actual-I/O smoke process runs once against each
prepared source tree. It covers exact BufferSource views; genuine file-backed File
objects and sliced reads; commit visibility; seek/truncate; abort preservation;
queued data and command snapshots; synchronous descriptor access; per-process
writer exclusion; directory and token boundaries; the unchanged production index
worker using real transferred buffers; and actual generation-media
stage/select/read/cancel/remove operations.

The pure Python comparator tests must run before those smokes. They acquire no
dictionary and exercise complete-field and finalized-file differences, generated
runtime drift, observer drift, missing native activation, parser group/CRC drift,
wrong source, cleanup failure and refusal to retire changed raw bytes.

## Preparation and invocation

Use Node v22.22.0 and Python 3.11 or later. The enclosing correctness workflow owns
fixture download and source preparation. It must check that both Git trees are
clean before generated setup.

Prepare the candidate with the repository's ordinary setup action. Prepare an
exact baseline checkout independently, sharing only the installed node_modules
dependency directory. Run npm run build:libs and npm run license-report:html
within each checkout; never share ext/ between the arms. The setup-generated
ext/legal-npm.html is the sole permitted tracked delta. Its original committed
and actual generated byte hashes are recorded, and the complete generated
runtime comparison still requires identical license-page bytes between A and B.

Fetch only the three pinned fixtures with the unchanged baseline-compatible helper:

    node dev/perf/prepare-dictionaries.js jmdict jitendex vndb

This populates builds/e2e-dictionary-cache. Each archive's exact SHA-256 and length
are checked against the unchanged test/perf/dictionaries.lock.json before the
study and before/after each import. The kit does not fetch fixtures or install
dependencies itself.

From the corpus directory, run the syntax and pure gates first:

    node --check node-opfs-disk.mjs
    node --check node-runtime.mjs
    node --check node-import-worker-bridge.mjs
    node --check test-opfs.mjs
    node --check run.mjs
    python3 test-run-all.py

Then run once:

    python3 run-all.py \
      --baseline-root /absolute/baseline-source \
      --candidate-root /absolute/candidate-source \
      --candidate FULL_IMMUTABLE_CANDIDATE_SHA \
      --fixtures /absolute/candidate-source/builds/e2e-dictionary-cache \
      --output /absolute/fresh-corpus-output

The output directory must not exist. Each full arm requires at least 4 GiB free
on a disk filesystem; Linux tmpfs is rejected. All corpora and arms are serial.
No browser is launched or installed by this kit.

The standalone Node smoke is test-opfs.mjs, not a Vitest-discovered *.test.* or
*.spec.* module. The Python test is test-run-all.py.

The earlier unexecuted corpus commit
8847aa8c11fc53a6de0439f09758d3cc01c21dbd over 9e10 remains provenance. Before any
execution, this new correctness kit moved to current develop dcfc02a0, which
includes the merged parser change from PR #972. The driver, adapter, bridge,
smoke, exact database-opening body, comparator policy and helper runtime are
unchanged. All already-frozen performance studies retain their original 9e10
sources; their observations are not relabeled or pooled with this new baseline.

## Production execution and optional native readiness

run.mjs imports the actual checked-out DictionaryImporter and DictionaryDatabase.
The normal compressed-source planner and actual parser/compression/index worker
modules execute through worker_threads. The bridge preserves real structured
cloning, SharedArrayBuffer visibility, transfer ownership, source-consumed messages
and completion messages. It records group source metadata and result row counts,
without changing grouping or parser flags. Exposed host capabilities are fixed to
hardwareConcurrency=4, deviceMemory=8 and crossOriginIsolated=true. The current
corpora must exercise three parser workers and 12/22/170 production groups.

The optional field encoder is initialized only by the real store begin-import
lifecycle. The driver does not import its helper, fetch its WASM, prewarm it, await
readiness or insert an asynchronous boundary around record encoding. A synchronous
observer invokes the original _encodeArtifactRecordFields once, immediately hashes
every returned byte, and reads the detached counters before/after that call.

The actual candidate must naturally perform at least one native field call. Every
call remains in the receipt, including pre-readiness JavaScript calls and declared
eligibility, memory-bound or unsupported-compact fallbacks. Zero activation fails
this correctness lane without a replacement import.

At each call and at final publication:

- calls equals the actual observed entries and nativeCalls + javascriptCalls.
- Native call and row deltas match the current observed field buffer.
- outputCopiedBytes increments by exactly the successfully native output length.
- All numeric native counters are nonnegative safe integers and monotone.
- nativeAttempts equals nativeCalls plus unsupported-compact, native-trap,
  native-return, native-header and output-copy declines.
- JavaScript calls equal calls before encoder readiness plus all decline counts.
- Nonzero guard-exception, native-memory-alias, memory-growth, input-copy,
  native-trap, native-return, native-header, output-copy, unavailable or unknown
  decline reasons fail the successful corpus gate.
- Database-forwarded terminal counters equal the owning store snapshot.
- The import owner is retired after final flush.
- The actual optional WASM fetch is witnessed once in B and never in A.

There is no cache of output hashes over mutable caller buffers. Hashing happens
synchronously before the original field output can be reused.

## SQLite host boundary

The full original _openConnection function text must equal the pinned
baseline-open-connection.txt in both arms before invocation. The harness rebinds
only that exact function's imported SQLite opening and diagnostic dependencies.
All original recovery, store preparation, schema, migration, health and media
cleanup calls remain in the production function body.

The real getSqlite3() engine is used. Opening selects new sqlite3.oo1.DB(':memory:').
Diagnostics explicitly identify nonpersistent memory SQLite. The
usesFallbackStorage=false route-selection override allows the real disk-backed
generation-media path despite that SQLite host substitution.

This establishes neither persistent SQLite behavior nor restart correctness,
browser OPFS semantics, image decoding or complete media qualification. Those
remain separate browser gates. skipImageMetadata=true and zipUseWebWorkers=false
are fixed host adaptations; skipMediaImport remains false. The original parser,
zstd and index workers still execute in real threads.

## Complete-byte oracle and source identity

Both arms hash every file in their complete generated ext/ tree before and after
import. Symlinks are rejected. Each generated native WASM is also checked against
the manifest and the pinned dev/data/dictionary-wasm artifact. The only complete
runtime differences allowed between A and B are:

- js/dictionary/dictionary-database.js
- js/dictionary/term-record-opfs-store.js
- js/dictionary/term-record-fields.js
- js/dictionary/wasm/term-record-fields.c
- lib/term-record-fields.wasm

All top-level kit files are bound in each receipt and must be identical across
arms. The enclosing source guard separately binds the full candidate Git tree,
product/test/build paths and correctness workflow before execution.

The oracle compares every synchronous encoded field buffer, every byte of every
final term-content file, every final record file, and every final lookup sidecar.
Only the documented 16-byte generation identity at MBTRD16X offset 8 or MBTIDX11
offset 24 is zeroed for normalized comparison, and only in the respective record
or lookup file. Raw SHA-256 and normalized SHA-256 are both retained. No field,
score, reference, index section or checksum is omitted.

Counts, sampled physical record bounds and live exact lookup results must also
match. Samples support the full byte oracle; they do not replace it. Actual
source-bank group boundaries and parser CRC/fallback work counts must match.
Rows must total exactly 528299, 436555 and 6648310 respectively.

Product code retains its normal internal clocks. This driver does not measure
process or import duration, compare speed or call a profiler. Product phase
receipts keep work counters while removing clock fields. Host smoke or audit
duration is never evidence about product performance.

## Evidence, failures and bounded storage

The output retains source, fixture, asset, worker, counter, complete field-call,
final-file, semantic, original process exit/log and cleanup receipts. Failed
attempts retain their available raw sink and partial inventories. A report
written before a later cleanup failure does not qualify as success.

Only after both original arms for a dictionary succeed and match, the
orchestrator independently streams and rehashes every raw generated disk file
against files.json. It then writes a retirement receipt and removes only those
owned successful disk directories. This is bounded retention of complete byte
digests, not retention of a full raw archive. Fixture/source/driver identities
remain sufficient to reconstruct a new explicitly identified run if separately
authorized.

The previous local JMdict attempt ended with process exit 137 and did not
establish whole-import parity. Its driver and static oracle strings were not
recovered after the executor interruption. They are not substituted here.

Original fields component run 46115204690 failed its compiler launcher before
any measurements or native rebuild/test outcome. Corrected component run
46123144616 is a distinct immutable study. Neither that original infrastructure
failure nor this new correctness kit creates a performance claim. Production
timing and any PR still require the separately frozen nomination/qualification
gates.
