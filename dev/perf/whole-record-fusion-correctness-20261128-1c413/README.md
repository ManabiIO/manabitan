# Native whole record fusion: fresh a300 correctness

This is an untimed correctness study for a new source revision. It does not
nominate a performance change or authorize a product PR. The earlier f28 native
field study, original imports, failures and completed records audit remain
immutable and rejected. No result from that source is transferred here.

## Validation

The first independent job runs the exact source guards, Node22.22.0 setup,
pinned LLVM/LLD21.1.8 reproduction of all three native targets, scoped product
lint, complete ordinary and options units, all main/dev/test type checks, and
all-target dry builds. Every gate outcome and log is retained even when another
gate fails.

The second job prepares A and B with separate ordinary `npm ci` installations
from equal lockfiles, then hashes every generated runtime file before any
product smoke or import. Exactly seven runtime paths may differ: the database,
record store, parser, field helper, prepared-metadata helper, field C source and
field WASM. The generated license document is recorded as a setup exception but
must still be byte-identical between A and B. No source difference is suppressed.

Pure comparator, owner-observer and archive tests run before any import. The
unchanged actual-I/O adapter smoke exercises disk handles, media capability and
the real index worker. Then fresh Node processes run JMdict A/B, Jitendex A/B and
VNDB A/B serially. The pinned archives, actual three-worker grouping, parser CRC
and fallback counters, all term rows, every synchronous field output and scalar
base, live sampled queries, and every finalized content/record/index byte are
compared. Initial and final source/fixture hashes must agree.

The candidate must activate whole fusion naturally for at least one actual call
and row in each complete corpus. This is a correctness activation gate, not a
coverage threshold selected from observations. No optional module preload,
readiness await, forced worker count override or replacement import is allowed.
All successful, ordinary-native, JavaScript-before-readiness and declined work
is retained. No exact number of whole calls is assumed before acquisition.

## Host and byte boundaries

The real bundled SQLite engine uses a nonpersistent `:memory:` database. Only
external storage dependencies of the exact current
`_openSupportedDictionaryConnection` method are rebound; its schema and root
admission checks remain intact. The outer `_openConnection` method remains
installed byte-for-byte. Both original bodies and the exact schema-version12
closure line are bound in source files. `usesFallbackStorage=false` is an
explicit adapter route-selection override, not a persistence claim.

This fresh-database lane requires the observed content root to begin at epoch0
and logical high-water0 and remain at epoch0. Legacy content segments use the
source-derived `manabitan-term-content[ ^N ].bin` naming convention (without
spaces). Arena/online content paths fail closed rather than escaping the byte
oracle. Upgraded roots, browser persistence, restarts, image decoding and full
media behavior are outside this Node lane.

Every final file is streamed and hashed. Only the documented 16 random generation
bytes in matching MBTRD16X record and MBTIDX11 index headers are normalized. Field
base scalars also retain their Float64 bit pattern so JSON cannot erase negative
zero. No content bytes, offsets, lengths, scores, lookup sections or other header
fields are ignored.

The enclosing owner observer accounts for native work moved ahead of the old
field hook. Its counters, exact Promise contract, overlap rules and copied-byte
ledger are described in `corpus/README.md`.

## Evidence and disposition

The acquisition keeps every original process log, outcome, source/runtime
inventory, field and owner receipt, native diagnostic, worker grouping, CRC
counter, complete final-file hash and failure. Successful raw sinks are retired
only after A/B equality and a second complete raw-byte rehash; their receipts do
not claim the raw files remain in the archive. Failed raw sinks are retained.
The link-safe PAX tar writer preserves filenames and inert symlink metadata
without following or extracting links, and verifies every regular payload
before artifact upload.

The unique push trigger has no path filter. It acquires no comparative timings,
browser runs or CPU-screen samples. Root review of the exact final source tree
is required before publication. Any future performance experiment is a separate
frozen source and protocol decision after this correctness gate.
