## Exactly one enclosing CPU interval

The named boundary is:

`first-product-module-evaluation-through-import-fixed-semantic-probes-and-retirement`

Source/fixture hashing, source guards, output-directory creation and common
host-adapter setup happen before the interval. Start before the first dynamic
import/evaluation of any arm-specific product module. Include product module
loading, SQLite/native compilation, normal store preparation and actual worker
creation/evaluation. A fresh process never reuses a compiled candidate module.

Run the actual importer. Its existing optional helper initialization remains
fire-and-forget through the production import lifecycle. Do not import the
helper early, await readiness, insert a new yield, or alter the first record
call's opportunity to fall back.

Keep the fixed live semantic probes inside this uninterrupted interval: record
bounds/sample, exact lookup and dictionary counts. Defer only their observer
hashes and serialization. Retain the original product reads/checks themselves.
The explicit boundary name discloses that this is import plus these probes and
retirement, rather than a claim about a narrower importer-only stopwatch.

End after final publication/flush, import-owner retirement, parser disposal,
database closure and actual worker termination/join. No startup or lifecycle
method is rebound to expose the fire-and-forget initializer. For a qualifying B
interval, all twelve successful whole-native calls and full work coverage prove
that its sole initializer assigned the encoder before use; the retired session
and unchanged close path prove disposal. A/C require stock metrics and no
optional asset fetch.

A failed or unactivated original attempt still runs normal parser/database/worker
retirement and retains its raw interval, but `endpointProven` is **false**. Late
initializer completion cannot be proven for such a failure. The mandatory endpoint
gate fails the entire original screen/replication. The row is neither removed nor
replaced. Focused product correctness retains late-init, cancellation and
unavailable-native coverage separately.

Read exactly one `process.cpuUsage()` snapshot at each endpoint. Primary CPU is
the difference in user plus system microseconds, divided by 1,000. This is one
process-wide measurement, including all actual worker and compilation threads;
never add worker/thread CPU or overlapping stage counters to it. Retain raw
snapshots and an enclosing `process.hrtime.bigint()` wall delta. Wall time is
secondary and cannot rescue a failed CPU gate. CPU may exceed wall time when
cores run concurrently; the exact Node version documents that behavior:

https://nodejs.org/download/release/v22.22.0/docs/api/process.html#processcpuusagepreviousvalue

No forced GC or repeated per-call loop is added. Source verification warms the
OS file cache; this is a fresh-process screen, not a cold disk/network estimate.

## Schedule and numeric nomination policy

Run two separately provisioned replications. Each has two excluded **untimed**
full warmup cycles and twelve measured blocks, one fresh process per arm entry.
There are 42 imports per replication: six warmups and 36 measured imports.
These are planned counts, not performed work.

R1 warmups: `ABC CBA`.

R1 measured blocks:

`ABC ACB BAC BCA CAB CBA ABC ACB BAC BCA CAB CBA`

R2 warmups: `CBA ABC`.

R2 measured blocks:

`ABC BAC ACB CAB BCA CBA ABC BAC ACB CAB BCA CBA`

R2 reverses the complete measured arm sequence of R1, then groups it into
triples. Each replication contains each permutation twice, each arm four times
in each position and every directed within-block adjacency four times. There is
no stronger claim about randomized order or cross-block transition balance.

Apply every gate separately within each replication:

| Requirement | Selected threshold |
| --- | --- |
| Median paired CPU saving, A minus B | At least 20 ms |
| Median paired CPU saving, C minus B | At least 20 ms |
| Median paired CPU reduction, B/A | At least 1% |
| Median paired CPU reduction, B/C | At least 1% |
| B faster than A | At least 10 of 12 pairs |
| B faster than C | At least 10 of 12 pairs |
| Absolute C/A paired-median percentage change | At most 3% |
| Absolute summed C CPU / summed A CPU change | At most 3% |
| Source, output, work, activation and lifecycle checks | Every observation passes |

There is no absolute millisecond control-drift gate. Ties are not faster pairs.
Percentages and absolute savings use each block's actual independent A/B/C
observations; neither a pooled control nor a ratio of medians substitutes for
the specified statistics. Retain all raw pairs and CPU/wall contrasts.

Both replications must pass individually. No pooling rescues a failure. No
retries, replacement imports, added observations, outlier removal or exclusions
beyond the declared warmups. A mandatory integrity failure stops that
replication's remaining schedule and preserves partial evidence; a quantitative
budget failure is reported after the fixed complete schedule. Do not cancel a
predeclared second replication merely because the first numeric gate failed.

The 20 ms floor is an engineering budget for deciding whether another browser
study is worthwhile. It is not a prediction of a 2% browser gain. No historical
Chrome stage value or old field-only saving is a current Node CPU estimate.

## Concrete disabled harness and receipt contract

`screen.mjs` orchestrates the fixed schedule and summarizes integer CPU receipts.
It has launched no workload. It has no product imports or clock reader and refuses
to launch while acquisition is disabled or any reviewed source/work/output
binding is unset. `corpus/run.mjs` now owns the real driver through the import-inert
`cpu-boundary.mjs` controller. The original numeric layer and its test receipt are
retained in `prior-numeric-layer/`.

The implemented, source-bound receipt adapter exports the read-only
`validatePreparedInputs({plan, workspace, arm, mode, replication})`, which runs
before each child is launched. It verifies the complete prepared runtime,
source tree, fixture, common harness, workflow and preparation binding and
returns `passed`, `sourceCommit`, `sourceTree`, `preparedRuntimeDigest` and
`fixtureSha256`. Mutable or wrongly prepared source must fail before a measured
import begins. The child receives the frozen plan path in the task-specific
`MANABITAN_RECORD_CPU_SCREEN_PLAN` variable plus the explicit workspace and
replication variables. It repeats its source guard before the first product import
and timer. The hosting workflow must set `NODE_DISABLE_COMPILE_CACHE=1` for the
orchestrator as well as its children; the parent preflight enforces it.

The same adapter exports
`validateObservation({plan, planSha256, workspace, directory, arm, mode, replication})`.
The explicit SHA is the hash of the exact frozen-plan bytes retained by the
orchestrator. It checks the original report's own source IDs, plan SHA, boundary,
array counts and owner accounting against independently recomputed evidence, then
independently checks original source/runtime, fixture, output, worker,
owner, activation, cleanup and raw receipt files and returns:

```text
{complete, arm, mode, sourceCommit, sourceTree, preparedRuntimeDigest, affinity,
 outputDigest, work, checks, timing}
```

`checks` must contain exactly the sealed `mandatoryCheckNames`, all true.
`work` must equal the sealed per-arm `expectedWork`. `timing` is null for
untimed warmups, otherwise raw `cpuBefore`, `cpuAfter`, `wallBeforeNs`,
`wallAfterNs` plus derived `cpuMs` and `wallMs`. The orchestrator independently
recomputes those values and the numeric gate. The implemented format is bound
to the copied current correctness source recorded in `copy-provenance.json`;
no historical field-only receipt is accepted as a whole-owner work observation.

CPU gate arithmetic uses original integer microseconds. Percentage medians and
summed ratios use exact rational threshold comparisons; displayed floating-point
percentages do not decide the gate. Exact inclusive boundaries such as 20 ms,
1% and either sign of 3% therefore need no discretionary tolerance.

Before acquisition, root must seal the prepared runtime identities, source-bound
driver/adapter inventory, work/output reference, exact mandatory checks, runtime
policy, preparation receipt and separately provisioned workflow. The complete
artifact auditor must inspect original archives/receipts and independently
recalculate both replications. No pass here authorizes a performance PR; a new
complete-browser qualification remains necessary. The closed historical f28
study and its gates stay unchanged.
