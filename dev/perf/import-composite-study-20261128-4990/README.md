# Composite delimiter study

This frozen study compares a native parser change with two identical unchanged
controls. It is independent of the adjacent-key screen: neither key-reuse
candidate is part of this product tree. The combined candidate enters an
adjacent object value directly after its validated key and colon, and consumes
consecutive matching container closers and their following comma without
redispatching each delimiter through the outer token loop. Every nesting,
required-field, grammar, media and normalization check remains in force.

The combined change was selected before any runtime performance comparison.
The separately retained close-only prototype supplies correctness context; it
is not an alternative timing cohort or a selected favorable result.

`protocol.json` fixes source, generated WASM, fixture lock, Node and Chromium
identities. Each dictionary has two independent hosted jobs. Each job builds
its own immutable release packages, checks the exact changed package members,
replays the complete native corpus, and uses three excluded warmups followed
by twelve balanced ABC blocks. A and C use the exact same baseline package in
fresh profiles; the second host reverses each block. The timing harness and
product defaults are unchanged.

Every ordinary run must pass the existing counts, sampled content/media,
lookup/restart and physical-storage receipt gates. Separate exhaustive media
checks, four process-tree memory observations and two profiling runs follow
the timed cohort. Memory and trace observations are never included in elapsed
comparisons. All failures, packages, source identities and raw reports are
retained. The prospective VNDB SAH policy is the source-bound current
37-allocation-unit baseline, with complete cross-arm file-size equality.

The runner rejects incomplete blocks, reports both candidate/control ratios
and the unchanged control ratio, and retains slow tails. It never subtracts
control drift or pools different hosts. A repeatable complete-import benefit
worth reviewing and the correctness/memory gates are required before opening
a runtime PR. No measured effect is presumed by this workflow.
