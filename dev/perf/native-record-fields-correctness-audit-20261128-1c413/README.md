# Read-only audit of the original native-fields correctness run

This kit reads the two immutable artifacts from original run **46132025311**, attempt 1, source **5c95580e99d0f1f57e0daef417753003c352e5b5**. It does not launch an importer, browser, compiler, native module, benchmark, replacement observation or polling job. The audit host contributes no performance measurements.

The original validation job is **140939066469**; its artifact is **15258022480**. The original corpus job is **140939066689**; its artifact is **15257853500**. Their exact names, sizes and GitHub SHA256 digests are frozen in `manifest.json`. The original artifacts and all earlier incomplete attempts remain unchanged.

## What is independently checked

The reader verifies original run, attempt, branch, source ancestry, terminal jobs and artifact association through explicit GitHub GETs. It hashes both complete downloaded ZIP files, validates canonical paths, rejects duplicate/type/size collisions, and records every member identity. The enclosing corpus PAX tar is separately bound to its producer receipt; every regular payload is streamed and hashed, and each symbolic link is compared as its original type and raw target. No symbolic link is followed, resolved, created or extracted. Hardlink tar records, sparse entries, unsupported metadata and path escapes are rejected.

The original writer regularized ordinary hardlinked files into full independent bytes. Pipe characters, Unicode, hidden filenames and original failed evidence remain in the retained archive. Raw disk payloads are hash-verified without extraction. The frozen producer sets `PYTHONDONTWRITEBYTECODE=1`; the reader does not claim it produced bytecode. Its only optional generated-source-cache allowance is the two exact known Python cache paths, preserved as opaque hash-only evidence and never materialized next to executable source.

Every archived tracked source must match its immutable Git blob. Required source files remain mandatory. Both original source guards must report the full changed-path set, all 21 protected baseline files, exact before/after native-asset inventories and the documented generated-license boundary. Complete generated runtime inventories must differ in exactly the five reviewed runtime entries. Each importer arm must match both its preflight and its post-import inventory.

For JMdict, Jitendex and VNDB, the reader recomputes complete synchronous field-buffer identity equality and the complete finalized term-content/record/lookup file map. Only the two documented 16-byte generation-ID ranges are normalized. Complete row counts and live lookup receipts must agree. Original process exits/log hashes, adapter smokes, cleanup, parser source-bank groups, original CRC/fallback counts and successful sink-retirement receipts are checked.

Recorded parser requests are joined to their terminal row counts. Ordered contiguous source-bank groups are then mapped to all downstream field-call row ranges. This explicitly distinguishes VNDB's parser-group count from field-call count; a field call cannot cross its actual source group. Scanned plus reused CRC bytes must account for all original source-bank bytes.

The optional helper must become ready through the actual production lifecycle. The reader never starts it. Before/after counters reconcile every encoder entry, native attempt, owned input/output copy, decline, natural pre-readiness JavaScript call, table allocation and bounded private page growth. Exact native layout and compact score-table sizes are recomputed from original counters and buffer sizes. Unknown or failed/disabled native paths cannot pass.

The separate original validation outcomes must match the job API and include every required gate and all ten workflow-produced logs. No unit/type/build command is rerun by the reader. The reader's own 30 synthetic regression cases cover archive, provenance, counter/layout, source-group, partial-failure and prerequisite boundaries.

## Limits of the evidence

The original corpus producer used a real nonpersistent memory SQLite engine plus the reviewed disk-backed OPFS-shaped adapter. Its source-bound successful raw sinks were fully rehashed and retired after comparison. This reader independently checks their retained complete-byte receipts; it does not pretend to reread retired bytes. It makes no browser persistence, restart, image decoding, complete-media or performance claim. Browser semantic, media, strict-memory and performance gates remain separate.

Earlier correctness attempts retain their original failures. In particular, run46129727075's complete console receipts were independently recovered, but its absent corpus artifact is not substituted for this run. This kit verifies only the new original source and observations listed above.

## Interface for the later browser records reader

Importing `audit.py` performs no network or product work. Explicit invocation is:

```python
result = audit_correctness(frozen_manifest, fresh_destination, api=None)
```

The default transport owns its own fresh output/API snapshots. The verified source module requires the exact neighboring `transport.py` and `field_activation.py` files. The latter is the already reviewed pure activation checker; only its pure counter validators are used here.

`browserPrerequisite` is emitted only from verified original evidence. It includes overall pass, exact product commit/tree and runtime SHA256 map, original run/attempt/job/head/artifact metadata, the original validation and corpus top-level receipt SHA256 values, and each dictionary's original comparison/report/field-call SHA256 values. A missing or failed prerequisite cannot become a passing browser launch or activation policy. This audit does not itself seal the prospective browser policies.

## Records-only workflow

The workflow uses pinned checkout, setup-python and upload-artifact actions on macos-15/arm64 with officially available Python3.12.10. It snapshots source before setup, verifies the exact source inventory, runs only the synthetic reader tests, then audits the exact two completed original artifacts. All original archives, API snapshots, member manifests, partial failures, source snapshots and results are uploaded even if a reader step fails. It never installs browser/npm dependencies.

A reader defect may be repaired in a separately identified reader revision over these same original bytes; such a repair is not a new import observation. No source edit, rerun or replacement of the original correctness jobs is authorized by this kit.
