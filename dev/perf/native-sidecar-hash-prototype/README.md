# Bounded native sidecar checksum experiment

Research only, based on develop `9e10d3b3fcf66d344ab31bc42c9b522fa5215da2`.
This directory changes no extension runtime or import settings. It screens
the current persisted XXH32 checksum against a bounded native implementation.
The seed remains `0x811c9dc5`, and every output must match the current hash.

## Mechanism and limits

The module owns exactly 64 KiB of fixed linear memory, of which 60 KiB is
streaming input scratch. It has no imports and cannot grow. An update carries
up to 15 bytes between calls. A separate stripe flag preserves long-input
finalization when the total length wraps modulo 2^32. Finish is nonmutating;
initialization clears all logical state. Scalar and SIMD variants use the
same algorithm, seed, admission rules, copy loop, and ABI.

The wrapper captures typed-array accessors and `set`, builds direct ordinary
views without invoking source species, and copies every admitted byte into
scratch before hashing it. Shared, resizable, subclassed, shadowed-metadata,
and native-memory-alias inputs retain the current JavaScript reader. Small
inputs also retain that reader. The checksum call is entirely synchronous;
there is no hash cache or state retained across an await inside a hash call.

Every timed native call includes admission checks, bounded input copies,
updates, and finalization. Module initialization is reported separately.
One fresh-process first-call diagnostic is also reported; it is not a paired
cold-start estimate. This is a component screen, not whole-import or browser
qualification. Runtime integration would need an existing import startup
overlap, explicit per-import ownership and release, and measured browser
startup and complete-import effects before a PR is justified.

## Reproduce

Use Node 22.22.0 or newer and the repository's installed dependencies/generated
libraries. The checked-in prototype modules were generated by Clang 21.1.8 and
LLD 21.1.8. Regeneration verifies both versions and records source/module hashes:

```sh
node dev/perf/native-sidecar-hash-prototype/build.mjs
node dev/perf/native-sidecar-hash-prototype/build.mjs --simd
```

Set `MANABITAN_CLANG` and `MANABITAN_WASM_LD` to the pinned executable paths if
they are not available as `clang-21` and `wasm-ld-21`. No C source in the shipped
dictionary module is changed by this experiment.

Independent correctness checks use 540 fixed upstream libxxhash 0.8.3 values
over five seeds and 13,240 partition/reset/continuation comparisons, plus 28
state-preserving rejected updates. The admission runner exercises 41 input
and fallback cases. Output paths must be fresh.

```sh
node dev/perf/native-sidecar-hash-prototype/verify-native.mjs dev/perf/native-sidecar-hash-prototype/xxh32-stream-simd.wasm /tmp/hash-vectors.json
node dev/perf/native-sidecar-hash-prototype/verify-admission.mjs "$PWD/dev/perf/native-sidecar-hash-prototype/native-checksum.mjs" "$PWD/dev/perf/native-sidecar-hash-prototype/xxh32-stream-simd.wasm" /tmp/hash-admission.json
```

Capture checksum spans from the locked JMdict, Jitendex, and VNDB ZIPs. The
script verifies archive SHA-256 and size, runs the native parser and actual
record encoder, and checks production checksum headers before writing spans.
Record references use deterministic content offsets; these receipts do not
claim parity with a fully installed database. No captured corpus is checked in.

```sh
node dev/perf/native-sidecar-hash-prototype/capture-first-bank.mjs "$PWD" /path/to/locked-fixtures /tmp/hash-first-groups --group
node dev/perf/native-sidecar-hash-prototype/screen.mjs /tmp/hash-first-groups /tmp/hash-group-screen.json 9 128 xxh32-stream-simd.wasm
```

Omit `--group` for the first bank. `--group` and `--all-groups` use the current
source's partition functions verbatim at hardwareConcurrency 4/deviceMemory
8. They parse each selected group synchronously, one group at a time, rather
than replaying worker scheduling. All-group mode verifies total row counts
against the fixture lock. Dictionary keys may follow the mode flag.

```sh
node dev/perf/native-sidecar-hash-prototype/capture-first-bank.mjs "$PWD" /path/to/locked-fixtures /tmp/hash-all-groups --all-groups
node dev/perf/native-sidecar-hash-prototype/screen.mjs /tmp/hash-all-groups /tmp/hash-all-screen.json 7 4 xxh32-stream-simd.wasm
```

The screen loads only one group's spans at a time. Its warm-up is explicit,
order uses seeded randomized ABBA blocks, and every block has an independent
JavaScript-versus-JavaScript A/A control. Each section is checked against its
saved checksum and SHA-256. The existing 151 independently pinned repository
vectors and shifted ranges are checked before timing. Per-group samples and
dictionary-wide sums are preserved; a hosted campaign should keep separate
fresh-process cohorts and inspect both timing and A/A distributions.

## Observed local screening

These runs share a noisy host. Ratios are native elapsed time divided by the
current JavaScript elapsed time; values below 1 favor native. All native timings
include input copies. The first bank uses 335,300 checksum bytes for JMdict,
91,360 for Jitendex, and 548,300 for VNDB.

| Variant | JMdict ratio | Jitendex ratio | VNDB ratio | Decision |
| --- | ---: | ---: | ---: | --- |
| Scalar global accumulators | 1.145 | 1.073 | 1.117 | Rejected |
| Scalar local accumulators | 1.191 | 1.127 | 1.098 | Rejected |
| SIMD first bank | 0.760 | 0.967 | 0.933 | Mixed; noisy controls |
| SIMD first current-policy group | 0.914 | 0.998 | 0.868 | Hosted screening only |

For the larger-group screen the corresponding A/A median ratios were 0.997,
0.960, and 0.988. Actual checksum spans totaled 1,828,740, 824,108, and 2,374,480
bytes across 50,000, 16,000, and 40,000 rows respectively. The Jitendex result
does not show a resolved gain. JMdict and VNDB warrant a controlled screen,
not a product PR. Compilation/initialization and first-call costs varied
substantially; no startup improvement is inferred from those single samples.

Raw local samples and independent checks are in `reports/`. Exact failed
scalar source/wrapper/harness/module snapshots are in `trials/`, so failed
experiments remain reproducible. The all-group mode is prepared for hosted
execution and has not been run locally.

The dedicated research workflow runs Ubuntu 26.04 and the repository's pinned
Node 22.22.0 setup. It independently rebuilds and byte-compares all four module
snapshots, checks vectors and admission, and captures the selected locked
dictionary in each matrix job. Three fresh Node processes then run seven
randomized ABBA rounds with four repetitions and A/A controls on every group.
All receipts and failures are retained; captured binary spans remain temporary.
