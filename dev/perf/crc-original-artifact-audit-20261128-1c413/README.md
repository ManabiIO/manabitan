# Original CRC gap slicing artifact audit

This job reads the original six-cell CRC gap slicing study and its separate
correctness artifact. It does not run a browser, install Node packages, import
a dictionary, invoke native code, sample processes, acquire benchmark timing,
rerun an original observation, or replace data. Audit-host durations have no
role in the original performance comparison.

## Existing pure validators and original failures

Only four exact baseline modules are imported after SHA-256 checks:
qualification_receipts, protocol, chromium_memory and audit_memory. The
caller invokes only pure receipt checks, the string memory overlay, recorded
sample summaries, the existing memory comparison and audit_cell. It never
invokes process discovery, process sampling, acquisition or a subprocess.
Linux gone-process errno compatibility is checked before reading records on
the macOS audit host.

The original common qualification module is never imported or executed.
Its pinned source is parsed as syntax, and only the single paired_summary
FunctionDef is compiled. A separate implementation must match every paired
ratio, median, equal-work ratio, faster count and the original seeded 10,000
bootstrap interval. Those results must equal the originally saved analysis.

The entire registered plan and exact memory overlay are checked. VNDB uses
the originally frozen explicit 37/37 SAH allocation units, with no policy
change. The same strict source/semantic/media receipts and raw process scan
validator are applied to the original bytes. Original memory semantic errors
are accepted only as faithfully reproduced failures, with the same name and
error text. Original raw-memory audit exceptions likewise must reproduce
the exact original type/message; conflicting success/failure receipts or
reader-induced mismatches fail the audit. Every such original failure remains
disqualifying, and no failed memory observation is discarded.

The CRC parser-phase extractor has the same source-bound constants and pure
field checks as the original audit-crc.py. It independently reads every raw
report, checks the exact bank boundary and safe integer metrics, and compares
the complete original crc-execution.json receipt. VNDB requires 170 groups,
665 banks, three parser workers, lead three, zero fused fallbacks,
568,284,368 scanned CRC bytes, 3,699,708,599 reused CRC bytes and 6,490,145
reused glossary witnesses in every report. JMdict and Jitendex retain their
original zero deferred-CRC totals and exact production grouping/source volume.

## Frozen decision policy

The primary target is VNDB. Both original target hosts must have at least a
2% paired-median complete-import reduction, at least 9/12 faster pairs, and
absolute A/C paired-median and equal-work changes no greater than 1%.

For each JMdict and Jitendex guardrail host, both absolute A/C measures must
be no greater than 3%. A repeated non-target regression means a slowdown
greater than 3% in paired median for the same dictionary on both original
hosts. Every isolated slowdown and raw contrast is still reported.

All six source/semantic/media/memory cells and the separate full correctness
gate must pass. These are the original prospective gates. No threshold is
selected from observations, no controls are subtracted, no hosts are pooled,
and no original observation is repeated or replaced.

A valid negative study is a successful read-only audit with qualification
false. Missing/inconsistent source, archive or record evidence fails the
reader, preserves partial evidence and cannot qualify the study.

The runtime WASM is exactly the same as already-open PR 979 (Git blob

This independent artifact audit is useful evidence for that runtime and
explicitly does not authorize a duplicate product PR or any peer contact.

## Output and verification status

The compact JSON printed to logs contains all original raw report durations,
separate nonauthoritative media/memory rows, per-host candidate and control
contrasts, strict memory failures/scan counts, source-bound CRC totals,
correctness evidence, the original job conclusions and all API/source/member
manifest hashes. Full original archives and detailed evidence remain in the
uploaded artifact. An audit error also includes any already read partial
observation rows.

Local execution is unavailable. The source is independently reviewed, then
the hosted records-only job verifies its own exact source and runs 20 pure
archive/identity/statistical/policy/CRC/failure tests before any artifact reads.
Neither source review nor reader construction is itself a benchmark result.
