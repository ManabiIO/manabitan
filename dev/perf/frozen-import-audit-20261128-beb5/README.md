# Audit fixed import artifacts

This workflow performs analysis of existing observations. It never launches a
browser, parser, native benchmark, import, fixture replay, or replacement timing
run. The original runtime candidates and measurement workflows remain unchanged.

## What is checked

The prefix analysis checks frozen executable/harness/registration identities,
strict package-member hash maps, complete six-treatment/six-control schedules,
three-pair flag-disabled controls and all four JMdict synthetic controls.
Every journal entry, including excluded verification invocations, must match the
saved report in exact order. Output digests, row counts, score/sequence types,
activation counters and source coverage are checked before full-work sums are
recomputed. Those sums remain group-by-group warm synchronous component work;
VNDB synchronous options are not production worker admission and first
verification order does not establish a cold-start effect.

The canonical portable auditor checks all original package bytes, observations,
semantic receipts, timing arithmetic, exhaustive-media receipts and the
prospective memory rules. A complete audit with a failed memory gate is
reported as such. Matrix fail-fast is disabled, and failure retention runs
unconditionally; one corpus cannot suppress the remaining reports.

Ubuntu 24.04 is used for standard-library Python artifact analysis only. It is
not a new benchmark host or an experimental arm.

## Acquisition and preservation

The job needs actions:read to obtain the exact existing artifacts. Authorized
GitHub API downloads are separated from unsigned redirect requests so the token
is never forwarded to the signed storage URL. Run/job/artifact metadata and
SHA256-verified original ZIPs are retained. Extraction rejects traversal,
duplicate members, symlinks and nonregular files; a complete original-member
census records sizes, CRCs and SHA256 hashes. Tokens and signed URLs are never
printed.

The optional final retention stage needs contents:write only to POST immutable,
unreferenced Git blobs. It does not update a ref, branch, commit, PR, workflow or
original artifact. Each uploaded blob is independently checked against its Git
object hash. Logs contain bounded JSON summaries and filename/size/GitSHA/SHA256
manifests so the root agent can review and anchor the objects in an evidence
commit. Unreferenced objects are not called durable until anchored.

Every prefix original ZIP is retained verbatim. Canonical durable archives keep
all original observation and log member bytes, except the exact reproducible
package-A.zip and package-B.zip members. The omission manifest, complete
original-member census, original outer artifact digest and full audit report
remain available. The re-created archive is explicitly not the original outer
ZIP. Full original ZIPs, including those package bytes, also remain in the
audit's Actions artifact. No sampled or failed observation is deleted.

The retained paths are restricted to
dev/perf/import-round-20261128-beb5/hosted-audit/<registered-entry>/.
Original fixed observations are never changed. Audit failure, memory failure
and an import performance conclusion are separate results.
