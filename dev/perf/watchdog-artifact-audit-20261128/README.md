# Original watchdog artifact audit

This job reads the original completed compression-watchdog screen. It does not
run a browser, install Node packages, import a dictionary, invoke native code,
sample processes, acquire timing, rerun a failed observation, or replace data.
The macOS audit host has no role in the performance comparison.

## Verification

The source binding verifies every auditor file before any network phase.
Exact auditor sources are copied to visible filenames in the retained artifact,
including workflow.yml, so hidden-file upload filtering cannot omit the workflow.
GitHub requests are GET-only. The API must still identify the exact original
run, head, branch, attempt, three terminal jobs and three original artifacts.
API metadata and each original outer ZIP's size and SHA-256 are checked.

The pure transport helper is Git blob
999868771f9f0c2ae9df861de3e5331e2ec89a72. It strips the GitHub token before
following a signed artifact redirect, rejects malformed JSON and nonfinite
numbers, and validates canonical ZIP paths, duplicate names, NUL truncation,
symlinks, file/directory collisions, encrypted members, directory payloads and
bounded expansion. No artifact-provided source file is executed.

Every outer archive member and every member of both original Chrome packages
is inventoried and hashed. The full original ZIPs and all extracted bytes are
retained, including any partial or invalid outcome. Package maps must equal
the executed source identities. Both independently built packages must have
identical entry sets and differ only in js/dictionary/zstd-term-content.js.
That entry must match the appropriate original Git source. Every other tracked
ext file present in a package also matches its original Git blob. The exact
baseline build copies tracked file bytes; its rewritten manifest.json is
generated and untracked, so it is reported among generated entries.

The source proof is independently checked against both immutable complete Git
trees, the sole parent, exact five changed paths, frozen runtime/test bytes and
all unchanged observer hashes. The actual runtime packages are fully present
for member verification. The optional chrome-dev.zip provenance hash is
retained and bound across reports; that development archive is not a runtime
input and is not independently present in the original artifact.

Only four exact baseline Python helpers are imported after SHA-256 verification:
qualification_receipts, protocol, chromium_memory and audit_memory. Importing
them performs no acquisition. The caller uses only their pure receipt checks,
string overlay, recorded-sample summarization, memory comparison and audit_cell.
It never calls process_inventory, read_smaps, sample_memory or run_with_sampling.
ENOENT and ESRCH numeric compatibility is checked before auditing Linux records
on macOS.

The original acquisition script is never imported or executed. Its verified
source is parsed as syntax, and only its single paired_summary FunctionDef is
compiled. An independently written contrast calculation must agree with that
function and with the original saved analysis, including all paired ratios,
equal-work ratios, faster counts and the original seeded 10,000-resample
descriptive bootstrap.

Each cell must contain exactly 42 original reports: four warmups, 24 measured
A/B observations, eight identical-code A/C observations, two exhaustive-media
observations and four separately instrumented memory observations. All
summary/raw/canonical receipts are recomputed. The original schedule, package
and source provenance, exact marker overlay, original marker bytes, individual
process scans, strict memory coverage and memory summaries are checked.
Instrumented memory and exhaustive-media durations are printed as separate
raw rows and never enter performance contrasts.

## Decision and preservation

A target is nominated only with at least a 2% paired-median complete-import
reduction, at least 9 of 12 faster pairs, absolute A/C paired-median and
equal-work changes no greater than 1%, all 42 source/semantic/media/memory
receipts, and the original full correctness gates. These are the pre-existing
screen gates; no threshold is selected from the data.

A negative but internally valid result is a successful audit with no nomination.
An invalid, incomplete, missing or inconsistent input produces a failed audit,
retains all downloaded original bytes and available receipts, and cannot
nominate a target. There are no retries, replacement observations, exclusions,
control subtraction, host pooling or benchmark setup steps.

The output root must be new. The job prints all 42 raw durations per cell with
role/order and explicit contrast eligibility, recomputed contrasts, control
gates, strict memory scan counts/failures, correctness evidence, and hashes for
the source/API/member manifests. Complete originals and detailed receipts stay
in the uploaded audit artifact.

This two-cell screen can only nominate a target for a separately frozen,
independent six-cell confirmation. It cannot by itself qualify a product PR.

Local execution was unavailable when this reader was authored. The hosted job
first verifies its own source and runs pure adversarial parser/identity/archive
and statistical tests before reading the original artifacts. The workflow pins
Python 3.12.10 for arm64, requires Python 3.11 or newer with assertions enabled, and has no
third-party Python dependency.

39b29ed91ea0ae26d8fc8f109ecef79c889827cf failed before source verification,
pure tests, or artifact reading. Its setup action could not find Python
3.12.12 for macOS 26.7.2 arm64. The official actions/python-versions manifest
has no macOS distribution for that security-only version. No new import or
original-artifact observation was acquired by the failed reader.

The corrected launcher uses the same pinned setup-python action with Python
3.12.10 and explicit arm64, whose official darwin-arm64 build is listed at
https://github.com/actions/python-versions/releases/download/3.12.10-14343898437/python-3.12.10-darwin-arm64.tar.gz.
It creates and snapshots its own setup evidence directory before Python setup,
so a future setup failure can still upload source and host evidence.
